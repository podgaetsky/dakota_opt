# Scientific curve audit (Dakota optional)

The optimizer objective, in-sample goodness of fit, predictive validation, local parameter inference, MCMC numerics and physical-model discrepancy are separate questions. This package does **not** report a single scientific score.

## Run without Dakota

From the repository root, with the Python dependencies in the root requirements installed:

    python -m fit_quality --reference templates/linear_benchmark/reference.csv --prediction templates/linear_benchmark/example_prediction.csv --parameters templates/linear_benchmark/parameters.json --parameter-definitions templates/file_benchmark.json --parameter-count 2 --noise-model templates/linear_benchmark/noise.json --output example_analysis

Inspect `example_analysis/report.html`, `report.json` and `residual_diagnostics.png`. The example is synthetic and not predictive validation. Omit `--noise-model` for descriptive curve error only. Parameters are physical values; `--parameter-count` is the number *fit on these data* (not necessarily the length of a parameter JSON). Missing parameter count means degrees of freedom and AIC/BIC remain unavailable.

Additional flags: `--validation-reference` and `--validation-prediction` accept a genuinely held-out, already-predicted curve; `--jacobian` takes an $N\times K$ headerless CSV of model derivatives with respect to **normalized parameter coordinates**; `--posterior-samples` is a draws-by-parameters headerless CSV; `--posterior-curves` is draws-by-ordinates *model prediction* CSV, not just parameter samples; `--weights` is an $N$-element comma-separated CSV of nonnegative integration weights. These files are optional; no supplied validation ≠ PASS. Independently evaluated whole held-out curves are preferable to random within-curve splits. To compare several independent curves, audit each held-out curve separately and report per-curve performance before pooling.

For several held-out curves or contiguous x-block predictions, `--validation-manifest heldout.json` accepts a list such as `[ {"name":"batch A", "kind":"independent curve", "reference":"data/a.csv", "prediction":"pred/a.csv"}, {"name":"region B", "kind":"blocked x", "reference":"data/b.csv", "prediction":"pred/b.csv"} ]`; paths are relative to the manifest. The model must have been trained/refit without those observations. The tool reports each curve separately plus pooled held-out RMS/MAE; it cannot itself establish that data leakage did not occur.

Noise JSON examples: `{ "sigma": 0.05 }`; `{ "sigma_i": [0.1, 0.2, ...] }`; `{ "covariance": [[...], ...] }`. For declared nonconstant noise, `{ "sigma_function": {"variable": "x", "coefficients": [0.01, 0.05]} }` means $\sigma(x)=0.01x+0.05$; `variable` can also be `predicted` or `observed`. Sigma must be finite and positive at every point; covariance must be symmetric positive definite. The correlated model uses Cholesky whitening, not diagonal approximation. Arbitrary custom likelihoods are **not** executed from untrusted JSON: they require a vetted code integration. The Dakota DREAM likelihood still only supports its existing scalar variance and cannot automatically use the covariance declared to `fit_quality`.

## Interpretations and equations

Given $r_i=y_i-f_i$:

* The optimizer minimizes **pointwise RMS** $\sqrt{\sum r_i^2/N}$. This favors regions sampled densely on a nonuniform grid.
* The optional **integrated** curve error is $\sqrt{\int w(x)r(x)^2dx/\int w(x)dx}$, computed using trapezoids. Changing weights changes the scientific target. Pointwise weighted RMS is also reported, separately.
* Gaussian $\chi^2=r^T\Sigma^{-1}r$; $\log L=-\tfrac12[\chi^2+N\log(2\pi)+\log|\Sigma|]$. Scalar sigma and `sigma_i` are diagonal special cases. Reduced $\chi^2=\chi^2/(N-k)$ is descriptive. A formal chi-square p-value is withheld unless the user explicitly passes `--chi2-test-justified` after establishing the Gaussian model, known noise and valid effective degrees of freedom; the flag is an attestation, not software proof.
* AIC $=2k-2\log L$, AICc $=\mathrm{AIC}+2k(k+1)/(N-k-1)$ when defined, and BIC $=k\log N-2\log L$. Use these to compare only compatible data, likelihood conventions and independently justified parameter counts. `python -m fit_quality.compare --models models.json --output comparison.csv` checks identical observed curves and noise JSON across candidates. Predictive validation complements information criteria.
* Residual ACF, Ljung–Box, runs, variance-trend associations, calibration regression, QQ and outliers are exploratory; no test proves independence, normality, correct physics or constant variance. If ordered residual structure is detected the report states **Independent-noise assumption is questionable.** With supplied covariance it diagnoses whitened residuals, while showing raw residual trends too. It never removes outliers.
* Local identifiability uses SVD of the optionally whitened normalized Jacobian. If full rank and the Gaussian likelihood is credible, $(J^T\Sigma^{-1}J)^{-1}$ is a *local linear approximation* to parameter covariance. It is not a global posterior, and hitting bounds invalidates naive symmetric intervals. An optional Python API `fit_quality.inference.finite_difference_jacobian(model, theta, lower, upper)` evaluates stable central/one-sided finite differences; you must budget its simulator calls. `fit_quality.profile.profile_objective(objective, optimum, bounds)` reoptimizes remaining parameters on a grid (multiple starts) to expose asymmetry and modes; `save_profile_figure(result, output, names, "RMS")` (or `"-2 log likelihood"`) plots the actual objective chosen. These are opt-in simulator calls, never inferred from one best curve.
* Posterior predictive figures use supplied **model curves at posterior draws**: latent model intervals and noise-added observation intervals are distinct. No GP uncertainty or model discrepancy is added implicitly. Samples alone without a callable model cannot produce these curves. DREAM R-hat/ESS/MCSE, prior/posterior and local exact-vs-GP checks remain in the existing Dakota pipeline.

## Dakota integration

`python tool.py opt templates/file_benchmark.json` now writes `provenance.json`, the original optimization report and `fit_quality/report.html`. Offline scientific audit runs even without a supplied sigma (then likelihood statistics are unavailable). `python -m fit_quality.robustness runs/RUN_A runs/RUN_B --output comparison.json` compares *independent* runs with identical parameter definitions; supply genuinely different starts/seeds. Fixed starts or correlated designs do not establish reproducibility. Existing async Dakota, native EGO and local/Slurm/allocation evaluators are unchanged.

Surrogates can be scored on **independent exact hold-outs** using `python -m fit_quality.surrogate --exact exact.csv --predicted gp_mean.csv --gp-sd predictive_sd.csv --output surrogate.json`. RMSE, MAE, max error and rank correlation are always computed; standardized errors, 95% interval coverage and negative log predictive density are calculated only if **GP predictive** SD is supplied (not measurement SD). Dakota's internal EGO GP is not exported here, so this is an interface for exported or independently trained surrogates, not a claim that Dakota EGO was validated.

For an actual independent-start experiment, use `python tool.py replicate templates/file_benchmark.json --repeats 3 --method opt` (or `--method bo`). This samples new initial parameter locations within each bound and new Dakota seeds, retains each run's separate report and saves `runs/*_robustness.json` with across-run objectives, normalized distances, boundary frequencies and convergence series. This addresses *optimizer reproducibility*, not intrinsic parameter identifiability. Make sure all runs use the same reference/model/noise; inspect each run's provenance.

Direct DREAM curve mode defaults to the **full observation curve** unless `--max-ordinates` or a template's `mcmc.max_ordinates` explicitly requests computational thinning. Thinning changes the likelihood and is recorded in `config.json`/the run report. Block aggregation, basis/PCA compression and correlated-data inference require a valid transformed likelihood and are **not** provided here; do not claim full-data equivalence. For large curves full-ordinate GPs may be expensive. Dakota's GP predictive variance is not exported in this workflow, so posterior-region exact-vs-GP checks cannot give predictive-interval coverage or NLPD; metrics needing that variance are marked unavailable.

## Limitations / evidence still needed

External held-out curves, domain-validated noise covariance, physical parameter priors, simulator-driven posterior curves, prior sensitivity, independent optimizer starts, model-discrepancy assessment, basis compression and Slurm execution all need user evidence or additional computational runs. Synthetic Gaussian coverage checks and SBC test software under their assumptions, **not** real-world physical validity. The scientific status table marks missing evidence UNKNOWN, not PASS.
